# 个人长期记忆

在 MobiAgent 里照常发送任务即可。电脑端会从你的原话中提取明确的个人事实和长期偏好，保存到本地，并在以后相关的任务里补全目标。重启电脑或服务后仍能读取。

## 可以怎么说

- 首次说明：`用百度地图导航回学校（北京信息职业技术学院东坝）。`
- 也可以照常说：`打开百度地图，再导航回学校 北京信息职业技术学院东坝 骑车。` 不要求括号或专用句式。
- 下次使用：`回学校。`
- 单独记录：`记住，我的公司地址是北京市朝阳区示例路8号。`
- 记录偏好：`记住，以后导航默认用百度地图。`
- 记录称呼：`记住，我说的老王就是微信里的王明。`
- 更正：`把我的公司地址改成北京市海淀区示例路10号。`
- 查看：`你记住了我哪些信息？`
- 遗忘：`忘记我的公司地址。`
- 清空：`清空我的全部记忆。`

以上是用法示例，不会预先写入你的记忆库。学校、公司、联系人等没有固定专用逻辑，同一种记忆结构可以保存其他明确关系和偏好。

纯记忆指令会在 App 的回复中给出记录、查询或遗忘结果，然后结束当前任务，不操作其他手机应用。信息不足时会在回复中询问；请在下一条消息里发出包含补充信息的完整任务。

## 文件位置

默认保存在项目根目录的 `memory` 文件夹：

- `user_memory.json`：实际读取的记忆库，包含条目、值、别名、用户原话依据及创建和更新时间。
- `MEMORY.md`：自动生成的可读版本，便于检查记住了什么。

如需手动修改，先停止服务，再编辑 JSON；Markdown 是查看用的镜像，直接修改它不会改变实际记忆。重新启动后会根据 JSON 重新生成镜像。记忆文件已加入 Git 忽略规则。

## 配置和启动

`cloud-config.json` 中的相关设置：

```json
{
  "memory_enabled": true,
  "memory_dir": "memory",
  "default_navigation_app": "百度地图"
}
```

这些字段与已有的 API Key、接口、模型等字段放在同一个配置文件中。相对路径以项目根目录为准。将 `memory_enabled` 改为 `false` 可停用记忆，已有文件会保留。

导航应用的选择顺序为：本次明确指定的应用、已保存的个人偏好、配置的默认导航应用。默认沿用当前部署在用的百度地图。

修改后，在原来的 CMD 按 `Ctrl+C` 停止服务，再运行 `start-cloud.cmd`。无需重新安装手机 App。首次创建的正式记忆库为空，测试示例不会混入其中。

## 记忆规则

1. 从当前用户原话提取事实，给每条事实保留依据。普通的“搜索某个地点”不会自动变成“我的学校/公司是该地点”。
2. 新说法明确更正旧事实时更新原条目；没有明确依据时不猜地址、身份或联系人。
3. 当前任务中的明确目标优先于旧记忆。例如已有学校地址时，`导航去天安门` 仍以天安门为目标。
4. 每个新任务只合并执行一次记忆理解和应用选择，后续截图沿用已补全的任务，避免每一步重复抽取和写入。
   记忆候选没有明确原话依据时不保存，不会因此让普通任务报错；如果实际目标缺失，会询问具体信息。单次任务里的“骑车”等条件会用于当前任务，只有明确说“以后默认”等稳定偏好时才长期保存。
5. 个人记忆保存在电脑文件中；当前指令和用于任务的相关记忆会发送到配置中的云端模型。不会训练模型或下载模型权重。
6. 当前版本是此电脑服务的单用户记忆库，不同手机连接同一个服务时会共用它。
7. 当前保存的是个人事实和偏好。手机每一步仍由当前截图决策，不会把旧点击坐标当作长期操作步骤重放。

本地库最多保存 256 条事实；超过上限会提示先删除旧事实。每次任务带入有限的候选记忆，再由模型选择实际相关条目；大量信息及非常隐晦的表达仍可能需要重新说明。
